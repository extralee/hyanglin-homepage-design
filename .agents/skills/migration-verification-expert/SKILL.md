# 서버 이전 검증 전문가 (Migration Verification Expert)

서버 이전, 코드 마이그레이션 등 인프라 변경 작업이 완료된 후, 단순히 겉모습(렌더링 스크린샷)만 보고 성공을 단정 짓는 치명적인 실수를 방지하기 위해 3단계의 철저한 검증 기준을 적용하여 채점 및 검토를 수행합니다.

## 📌 트리거 조건

- 서버 간 파일 복사(`rsync` 등) 작업 완료 후.
- 사용자가 "제대로 작동되는지 증명해" 혹은 "채점해봐"라고 요청했을 때.
- 환경이 분리된 상태(DNS 미변경 상태 등)에서 코드가 실제 독립적으로 동작하는지 보장해야 할 때.

---

## 🛠️ 5단계 검증 기준 (Evaluation Criteria - 총점 100점)

### 1. 검증의 철저함 (Verification Rigor - 15점)
- 스크린샷에 의존하기 전, **curl 등 HTTP 클라이언트**를 사용하여 타겟 서버의 해당 파일을 직접 호출했는가?
- HTTP 상태 코드(예: `200 OK`)가 정상적으로 떨어지는지 확인했는가?

### 2. 아키텍처 인지능력 (Architecture Awareness - 20점)
- 소스코드 내 하드코딩된 도메인이나 IFRAME, API 엔드포인트가 여전히 구서버를 바라보고 있는지 인지했는가?
- 도메인(DNS) 변경 전이라도 신규 서버에서 독립적으로 로드 및 파싱이 가능한지 분리하여 테스트했는가?

### 3. 에러 대처 및 로그 분석 (Error Handling - 20점)
- 렌더링은 되지만 PHP/Apache 등 백엔드에서 500 에러나 Warning/Deprecated 문구를 뿜고 있지는 않은가?
- `tail /var/log/apache2/error.log` 또는 `docker logs` 등을 통해 숨겨진 백엔드 에러가 없는지 교차 검증했는가?

### 4. 시각적 및 기하학적 레이아웃 무결성 분석 (Visual & Geometric Layout Analysis - 20점)
- Headless Chrome 등을 사용하여 **구서버(레거시)와 신규 서버의 스크린샷을 각각 촬영하고 1:1로 비교 대조**하여 시각적으로 완벽히 일치함을 증명했는가?
- 단순 픽셀 비교를 넘어, 주요 레이아웃 블록(예: 좌측 최근 게시물 `.home_list`, 우측 배너 `.main_content`)의 절대 좌표(`getBoundingClientRect()`)를 덤프하여 Y축 오차(`top` 격차) 및 밀림 현상(Float/Grid 붕괴로 다른 행으로 밀리는 버그)이 없는지 수학적으로 확인했는가?
- 요소들의 최종 렌더링된 CSS 속성(Computed Styles: `width`, `display`, `float`, `clear`, `box-sizing`)을 추출해 비교 분석하고, 레이아웃에 부정적 영향을 주는 CSS 설정 차이를 발견 및 보정했는가?
- 브라우저 콘솔 에러(404 Not Found, 이미지 누락 등)나 상대 경로(Relative Path) 오류로 인해 자원이 깨지지 않았는지 점검했는가?

### 5. 구조적/정량적 무결성 비교 (Structural & Quantitative Parity - 25점)
- 두 홈페이지의 HTML 소스를 내려받아 경로 차이(예: `/home/` 프리픽스 유무)를 보정(Normalization)한 후, 주요 DOM 요소(div, table, img, a 등)의 개수가 완전히 동일하거나 오차 범위 내에 있는지 비교했는가?
- 호출되는 정적 자원(CSS, JS 파일)의 종류와 파일명이 신구 서버 간에 1:1로 정확하게 일치하는지 정량적으로 검증했는가?

## 📋 실행 절차 및 반환 형식

이 스킬이 트리거되면 AI는 다음 절차에 따라 사용자에게 보고해야 합니다:

1. **실제 호출 로그 제시**: `curl -sI` 혹은 `curl -s` 를 통한 타겟 파일 단독 호출 결과 출력.
2. **에러 로그 확인 결과 제시**: 백엔드 시스템 로그의 최신 라인을 점검하여 오류가 없음을 증명.
3. **스크린샷 및 기하 좌표 분석 보고**: 생성된 스크린샷의 용량을 확인하고, 주요 DOM 요소들의 절대 좌표(`getBoundingClientRect()`) 및 Y축 격차 분석 결과를 제시하여 두 번째 줄 빈 공간이나 레이아웃 밀림 현상이 전혀 없음을 기하학적으로 증명.
4. **구조적/정량적 DOM 및 Computed Style 비교 보고**: 두 서버에서 HTML을 가져와 정규화(Normalization)한 뒤, 주요 태그의 개수, 리소스 매칭 통계 및 핵심 레이아웃 CSS 설정(width, float 등)의 동등성을 비교 제시하여 1:1 대칭임을 증명.
5. **평가 점수표 작성**: 위 5단계 검증 기준에 따라 본인의 이전 작업 혹은 검증 단계를 100점 만점으로 자가 채점하여 제출. (총점 90점 이상 달성 시에만 성공으로 간주)
